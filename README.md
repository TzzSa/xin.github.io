# 💛 我们的小日子 · 情侣互动小网站

一个**纯前端、零后端、零依赖**的情侣互动网页。所有数据只存在各自浏览器本地，不需要数据库，不需要服务器，直接丢到 GitHub Pages 就能用。

---

| 特性 | 说明 |
| --- | --- |
| 恋爱计时器 | 精确到秒的在一起时长，天/时/分/秒实时跳动，天数变化带滚动动画 |
| 纪念日倒计时 | 支持年度重复，进度环显示"已经走过百分之几" |

## 🚀 部署到 GitHub Pages（三步）

**第一步：新建仓库**
在 GitHub 新建一个仓库（例如 `our-days`），**Public 或 Private 都可以**（Private 仓库也能开 Pages）。

**第二步：上传文件**
把下面 5 个文件**全部放在仓库根目录**（不要放进 `assets/` 之类的子目录）：

```
index.html
style.css
core.js
app.js
README.md
```

可以用网页上传，也可以用命令：

```bash
git init
git add index.html style.css core.js app.js README.md
git commit -m "init: 我们的小日子"
git branch -M main
git remote add origin https://github.com/<你的用户名>/our-days.git
git push -u origin main
```

**第三步：开启 Pages**
仓库 → `Settings` → `Pages` → Source 选 `Deploy from a branch` → Branch 选 `main`、目录选 `/ (root)` → Save。

等 1～2 分钟，访问 `https://<用户名>.github.io/our-days/` 即可。

> ⚠️ 页面里所有资源都用的是**相对路径**（`core.js` 而不是 `/core.js`），所以放在子路径下也能正常加载。

## 🔗 分享机制：它是怎么工作的

这是本项目最核心的设计，回答三个问题：

### 1. 很多人访问，数据会串吗？

**不会。** 浏览器的同源策略决定了：`localStorage` 是按「域名 + 端口」隔离的，并且只存在于**访问者自己的那台设备、那个浏览器**里。别人打开同一个网址，读的是他自己浏览器里的空数据。物理层面就不可能串。

### 2. 那分享链接怎么让 TA 看到"我们的计时"？

方案是 **URL hash 分享码**，纯 JavaScript 实现，不需要任何后端：

```
生成端                                      接收端
──────                                      ──────
读取本地设置（纪念日、昵称）        →       解析 URL 中 #d= 后面的分享码
JSON → Base64（URL 安全字符）       →       解码 → 写入 TA 自己的 localStorage
拼成 https://xxx/#d=eyJ2Ijox...    →       立刻显示你们的计时器
```

代码位置：

- `core.js`：`encodeShare` / `decodeShare` / `buildShareUrl` / `parseShareHash`
- `app.js`：`buildShareUrl()` 生成链接、`tryImportFromShare()` 导入数据

关键点：

- 数据放在 **`#` 后面**（fragment），不是 `?` 查询参数。浏览器**不会把 hash 发送到服务器**，比 query string 更私密。
- Base64 做了 URL 安全处理（`+` → `-`，`/` → `_`，去掉 `=`），中文昵称和 emoji 经过 UTF-8 编码，往返无损。
- 导入成功后会调用 `history.replaceState` **把 hash 抹掉**，避免 TA 刷新页面时反复弹覆盖确认。
- 如果 TA 本地**已经有自己的数据**，会弹确认框询问「要用这个链接的数据覆盖吗」，不会无声覆盖。

### 3. 直接访问网址（不带分享码）会怎样？

**空白的引导页。** `parseShareHash` 对空 hash 或残缺/损坏的分享码一律返回 `null`，页面走正常的首次设置流程，不会有任何覆盖行为。

### 生成分享链接

点右上角 **🔗** 按钮（或 ⚙ 设置 → 分享备份 → 生成链接），复制发给 TA 即可。

## 📱 移动端适配

**是，手机端是完整可用的**，不是「能打开但难用」。具体做了这些：

| 项 | 做法 |
| --- | --- |
| 视口 | `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` |
| 布局 | 全部流式，容器 `max-width:720px` 居中；断点 `520px` 与 `360px` 两级 |
| 刘海/底部横条 | 顶栏、Toast、页脚都用了 `env(safe-area-inset-*)`，内容不会被遮挡 |
| 高度 | 用 `100dvh`（带 `@supports` 回退），地址栏收起/展开不会跳 |
| 弹层 | `max-height:86dvh`，避免底部按钮被地址栏挤出屏幕 |
| 输入框 | 触屏设备一律 `font-size:16px` —— iOS Safari 在聚焦小于 16px 的输入框时会**强制放大整页且不还原**，这是手机上最影响观感的一个坑 |
| 触控目标 | 按钮、图标按钮、色块、删除键在窄屏统一放大到 ≥44px |
| 手势 | 游戏画布用 `pointerdown/move/up`（不是鼠标事件），支持触屏与手写笔；`touch-action:none` 防止刮卡/画画时页面跟着滚 |
| 点按延迟 | `touch-action:manipulation` 去掉移动端 300ms 点击延迟 |
| 高清屏 | Canvas 按 `devicePixelRatio` 缩放（上限 2 倍，兼顾清晰与性能） |
| 横竖屏 | 旋转后自动重排画板与刮刮卡画布，刮到一半的进度不会被清掉 |
| 触屏 hover | 触屏设备上中和会「粘住」的 hover 位移，点按反馈交给水波纹与 `:active` |
| 省电 | 切到后台自动暂停背景动效；窄屏粒子从 14 个降到 8 个 |
| 减少动效 | 跟随系统 `prefers-reduced-motion`，开启后关闭全部动画 |

> 建议在手机浏览器里用「添加到主屏幕」，打开体验更接近原生 App。

## 📁 文件结构

```
.
├── index.html    # 页面结构（背景动效层 + 引导层 + 计时视图 + 游戏视图 + 设置弹层 + 名字弹层）
├── style.css     # 样式（奶油暖白手账风 + 背景动画 + 交互动画 + 响应式）
├── core.js       # 纯逻辑层：存储/日期/随机/配置合并/分享码（不碰 DOM，可单测）
├── app.js        # 交互层：渲染、事件、8 个游戏、内容配置编辑器
├── test.js       # 逻辑层测试（可选，部署时不需要上传）
└── test-dom.js   # 交互层测试（可选，部署时不需要上传）
```

**为什么拆成 `core.js` 和 `app.js`？**
`core.js` 不依赖 DOM，可以在 Node 里直接跑单元测试（日期计算、配置合并、分享码编解码、随机数这些最容易出错的地方都有覆盖）。`app.js` 只管界面和交互。

`app.js` 的启动顺序：工具与动效 → 配置读取/迁移 → 分享码 → 引导 → 视图切换 → 计时器 → 纪念日 → 8 个游戏 → 名字弹层 → 设置与内容配置 → 启动。

## 🧩 内容配置是怎么实现的

配置集中存在一个对象里（`localStorage` 的 `love.config`），启动时与默认值**深合并**，所以以后加新字段也不会让老用户的配置失效：

```js
var DEFAULTS = {
  quiz:    { questions: [...] },          // 列表，最多 50
  wheel:   { items: [...] },              // 列表，最多 50
  scratch: { cards: [...] },              // 列表，最多 50
  tap:     { duration: 30 },              // 数字
  ten:     { target: 10 },                // 数字
  memory:  { emoji: [...], words: [...] },// 两个列表
  draw:    { words: [...], duration: 60 },// 列表 + 数字
  truth:   { truth: [...], dare: [...] }  // 两个列表
};
```

设置面板里的编辑器由 `CFG_SCHEMA` **自动生成**——想加一项配置，只要往 schema 里加一条：

```js
{ path: 'tap.duration', name: '💛 爱心手速 · 单局时长',
  type: 'num', min: 5, max: 120, step: 5, unit: '秒', def: 30, hint: '5–120 秒' }
```

`type: 'list'` 会渲染成多行文本框（带 `n / 50` 计数与去重），`type: 'num'` 会渲染成数字输入框（自动夹紧到 min–max）。

**旧版本迁移**：如果你之前用的是把配置写死在 `app.js` 里的老版本，首次打开会自动把 `love.wheel` / `love.truth` / `love.mem` 里的内容搬进新配置，然后删掉旧键，不需要手动操作。

## 🎨 改配色

编辑 `style.css` 顶部的 CSS 变量：

```css
:root {
  --cream:   #FFFCF7;  /* 背景奶油白 */
  --card:    #FFFFFF;  /* 卡片底色 */
  --ink:     #4A3B2E;  /* 主文字色 */
  --honey:   #E8A05C;  /* 主色调（蜂蜜橙） */
  --honey-d: #C97B3C;  /* 主色调深（按钮按下） */
  --peach:   #F6C9A8;  /* 辅助色（蜜桃） */
  --rose:    #E8907E;  /* 点缀色（玫瑰） */
  --mint:    #8FBFA8;  /* 点缀色（薄荷） */
  --line:    #F0E4D4;  /* 分隔线 */
}
```

背景动效的强度在 `.bg-fx` 相关规则里调：`.glow` 是三个缓慢漂移的光斑，`.bg-fx .p` 是漂浮粒子（数量在 `app.js` 的 `bindBgFx` 里，宽屏 14 个、窄屏 8 个）。不想要背景动效，删掉 `index.html` 里的 `<div class="bg-fx">` 即可。

页面切到后台时会自动冻结背景动效（给 `body` 加 `.bg-paused`），避免白烧电。

所有动效都会遵守系统的「减少动态效果」偏好（`prefers-reduced-motion`），开启后会自动关闭。

## 🔒 隐私说明

- 所有数据存在浏览器 `localStorage`，**不上传任何服务器**。
- 分享链接和备份口令里的数据是明文 Base64（**不是加密**）。它不会经过服务器，但内容如果被人拿到，就能看到里面的纪念日日期和昵称。介意的话建议用私密渠道发送。
- 如果仓库是 **Public**，你的网页内容（代码、题库）全网可见——但**访客数据仍然互相隔离**，这点不受影响。
